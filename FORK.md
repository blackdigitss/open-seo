# This fork

`blackdigitss/open-seo`, forked from [`every-app/open-seo`](https://github.com/every-app/open-seo).

Goal: make our own changes freely, but still take upstream's releases with a
low-drama merge. The whole strategy is one idea — **keep our changes additive
and out of upstream's way** — so most merges are trivial. The product plan and
the reasoning behind these conventions live in [`DECISIONS.md`](./DECISIONS.md).

## Branches

| Branch                | What it is                                                   |
| --------------------- | ------------------------------------------------------------ |
| `main`                | Ours. Upstream + our customizations. Deploys come from here. |
| `upstream/main`       | Their repo (a remote, not a branch we commit to).            |
| `sync/upstream-<tag>` | Throwaway review branch where an upstream release is tested. |

Upstream never merges straight into `main`. It lands on a `sync/*` branch,
gets reviewed and built, then merges.

## Taking upstream changes

We sync against upstream **release tags**, not whatever is on their `main`
on a Monday — the maintainer reverts within the week often enough that HEAD is
not a safe target.

Automatic: `.github/workflows/sync-upstream.yml` checks every Monday for a tag
newer than the last one we merged. Clean merge → a PR; conflict → an issue.
Nothing lands without a human merging it.

Manual, any time:

```bash
./scripts/sync-upstream.sh          # what the newest release changed + which files will fight us
./scripts/sync-upstream.sh --merge  # merge that tag on a sync/ branch
```

Then:

```bash
pnpm install && pnpm build && pnpm test
git checkout main && git merge sync/upstream-<tag>
pnpm deploy:selfhost --yes
```

`src/routeTree.gen.ts` is git-tracked and both sides add routes; the sync
script regenerates it instead of merging it.

## Where our code lives

Upstream will never write to any of these, so they never conflict:

| Path                      | What                                                                     |
| ------------------------- | ------------------------------------------------------------------------ |
| `src/custom/**`           | Services, jobs, components, the scheduled Worker entry                   |
| `src/db/custom/**`        | Our tables — D1 schema, Postgres mirror, our own parity test             |
| `drizzle/custom/**`       | Our migrations, own journal, generated by `drizzle-custom.config.ts`     |
| `src/routes/**`           | Thin route files that import from `@/custom` (new files only)            |
| `wrangler.custom.jsonc`   | The scheduled Worker: same D1/KV ids as the app, plain `wrangler deploy` |
| `DECISIONS.md`, `FORK.md` | This documentation                                                       |

Rules that keep this cheap:

1. **Scheduled work runs in the custom Worker, not `server.ts`.** The audit
   Worker is the precedent. This keeps `server.ts`, `wrangler.jsonc` and
   `alchemy.run.ts` — three of upstream's hottest files — untouched.
2. **Custom tables are never re-exported from upstream's schema barrels**
   (`src/db/schema.ts`, `src/db/d1/schema.ts`, `src/db/pg/schema.ts`) and
   never added to upstream's parity test. Repositories import from
   `src/db/custom` directly.
3. **Custom migrations go in `drizzle/custom/`**, applied by alchemy after
   upstream's with no configuration change. Local dev applies them with
   `wrangler d1 migrations apply DB --local -c wrangler.custom.jsonc`.
4. **No new npm dependencies** for things the platform already provides:
   WebCrypto for push keys, `fetch` for HTTP APIs, OpenRouter (already
   installed) for LLM calls. `package.json` changed 26 times in 60 days.
5. **Every hook into upstream code is a dynamic `import("@/custom/...")`**,
   so nothing of ours enters the eager Worker bundle that the lean-bundle
   plugin guards.
6. **Mark every edit to an upstream file:**

   ```ts
   // FORK: <what and why>
   ```

   `grep -rn "FORK:" src *.jsonc` lists our entire footprint in upstream
   code. Keep that list short and keep it in the table below.

7. **Prefer cold files for hooks.** `navigation/items.ts` and `__root.tsx`
   changed once or twice in 60 days; `mcp/server.ts` changed twelve times.
   If a hook must go in an append-style list, put it at the **top** —
   upstream appends at the bottom.
8. **Contribute upstream through issues**, with a POC branch linked as
   reference. Upstream does not accept PRs (`docs/CONTRIBUTING.md`); anything
   they build from our issue is one less thing we carry.

## Deploying

See `docs/SELF_HOSTING_CLOUDFLARE.md`. Config lives in `.env.selfhost`
(gitignored). App: `pnpm deploy:selfhost --yes`. Scheduled Worker:
`wrangler deploy -c wrangler.custom.jsonc`.
